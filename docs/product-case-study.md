# Boom Moment 产品案例

**Live Demo：** [https://boom-moment.netlify.app](https://boom-moment.netlify.app)

**仓库：** [https://github.com/cookie536/boom-moment](https://github.com/cookie536/boom-moment)

**产品说明：** [README](../README.md)

**开发规格：** [Boom Moment Development Spec v1.0](../Boom_Moment_Development_Spec_v1.md)

我独立完成了产品策划、需求定义、交互设计、AI 辅助开发、测试验收与上线部署。本文记录的是 2026 年 10 月这一版公开测试站的实际过程，没有团队分工、用户规模或增长数据。

## 为什么做这个产品

我想要一个能在手机上马上记下灵光的工具。现成笔记应用通常把分类、同步和账号放在记录前面。对一条还没成型的想法来说，这些步骤太重。

另一个具体问题是两条想法之间的关系。它们可能分别躺在不同记录里，重新打开时已经看不出当时为什么相关。我需要一种轻的连接：先把两条放在一起看，再决定只记住这层关系，还是把碰撞出来的新想法写成第三条。

因此 Boom Moment 的定位是私人灵感记录本。先记 Moment，再用 Space 收纳，用 Boom 连接。不注册，不上传内容，数据留在当前浏览器。

## 如何确定 MVP

范围写在 [v1.0 开发规格](../Boom_Moment_Development_Spec_v1.md) 里，并按依赖拆成四段，前一段验收通过才进入下一段。

| 阶段 | 纳入 | 暂时不做 |
| --- | --- | --- |
| A. 记录 | 新建、编辑、图片、详情、首页卡片/列表、搜索、刷新后仍在 | 账号、云同步、标签、社交 |
| B. 空间 | 嵌套空间、未分类、移动、删除后归位 | 一条记录属于多个空间 |
| C. Boom | 选择两条、建立连接、取消连接、保存后才连接新 Moment | AI 碰撞文案、动画表演 |
| D. 带走 | 设置、ZIP 备份与恢复、单条分享图、数据丢失提示 | 自动同步、暗色模式 |

取舍标准是：没有这条，用户能不能完成「记下、找回、关联、换浏览器前带走」。不能靠它成立的能力都延后。AI 整理和知识树做过早期试验，但没有放进 v1 底栏。主流程不生成用户没写过的文字。

## 从需求到上线

1. **写成可执行规格。** 规格固定了数据模型、中文文案、黑白移动端样式，以及 Moment、Space、BoomLink 的关系。一条 Moment 最多一个空间。Boom 连接不分方向，同一对只保留一条，不能自己连自己。
2. **按阶段实现并验收。** 记录先保证刷新后文字和图片都在。空间再保证移动和删除空间不会弄丢正文、图片和连接。Boom 再保证取消编辑不会留下半成品连接。备份和分享放在功能可用之后。
3. **只改交互，不改模型。** 第一版 Boom 和 Space 能用之后，验收时发现选择路径和归类路径都不够直接。v1.0.1 只调整这两个流程，继续使用原来的 IndexedDB，不覆盖已有数据。
4. **准备公开访问。** 确认生产构建不依赖本机服务器，设置页写明数据只在当前浏览器，并补上主屏幕所需的名称、图标和 Manifest。API Key 没有进入 Git。
5. **发布。** `main` 推送到 GitHub 后，公开站点发布在 Netlify：[boom-moment.netlify.app](https://boom-moment.netlify.app)。

实现使用 AI 辅助开发。我负责决定做什么、不做什么，并在浏览器里验收。

## 用户反馈如何推动交互迭代

这里的反馈来自我自己按真实使用路径做的验收，不是外部用户研究，也没有样本量。

**Boom。** 第一版可以选出两条记录并建立连接，但选择和对照混在一起，已有连接也不够显眼。验收后改成：底栏进入独立选择页，能搜索并按空间筛选；勾选满两条才出现「开始 Boom」；对照页同时展示两条的标题、正文和图片；然后明确选择「仅建立 Boom 连接」或「建立连接并创建新 Moment」。已有连接留在页面上，可以取消。连接规则没有放宽。

**Space。** 在空间里新建记录是够的，但已有记录要一条条改归属。验收后增加「添加已有 Moment」：默认列出未分类，可搜索、可多选，一次移入当前空间；也可以从其他空间选，并写明这是移动而不是复制。移动后当前空间和未分类列表立刻更新，刷新后仍然在。

两次迭代都没有新增 AI，也没有改 Moment 和 Space 的核心字段。

## 测试、部署和发布

验收不以页面能打开为准。每段至少检查：

- TypeScript、Lint 和生产构建
- 手机宽度下的主路径，包括空状态、取消和刷新
- IndexedDB 里的正文、图片、创建时间和连接是否还在
- 用本地检查脚本覆盖记录、空间、Boom 去重和备份往返

备份曾经在脚本里通过，但在真实浏览器里合并失败。原因是在同一次写入事务中读取图片内容，事务被提前结束。修正后改为先读完，再单独写入，并重新在浏览器里确认原有记录没有被改掉。

公开前还检查了这些事：生产构建可以独立运行；`.env.local` 被忽略，构建产物里没有 API Key；设置页能看到备份提示；iPhone 可以通过 Safari 添加到主屏幕。部署时没有配置 AI 密钥。站点是静态可访问的 Next.js 应用，每个访客的数据仍在自己的浏览器里。

## 后续可能的产品方向

还没有排期，也还没有用户数据支持优先级：

- 把「请导出备份」从一句说明变成更及时的提醒。
- 让一段时间里的记录更容易回看，同时继续不强迫分类。
- 评估离线可用是否值得做。当前没有 Service Worker。
- 若重新考虑 AI，只作为用户点下的一步，例如整理刚写下的一条，而不是自动生成 Boom 结果。
- 决定是否从公开站点移除早期的资料库和 AI 试验页面，避免和 v1 主流程混在一起。
